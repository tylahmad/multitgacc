# tgmultipanel — مدير جلسات Telethon (واجهة سطح مكتب)

`ahmadtgmulti.py - tgmultipanel | مدير جلسات Telethon`

واجهة رسومية (PyQt5) تعمل على Windows تستبدل بوت التحكم القديم في تيليجرام،
مع الحفاظ على **نفس محرك التنفيذ** (`worker.py` + `ai_agent.py`) دون تغيير منطق المهام
أو السرعة أو التأخيرات. البرنامج **محلي بالكامل**: لا Supabase ولا ملفات `.env` ولا توكن بوت.

---

## 1) المتطلبات

| العنصر | الملاحظة |
|---|---|
| Windows 10/11 (أو Linux/macOS) | يعمل على أي نظام يدعم PyQt5 |
| Python 3.9 أو أحدث | حمّله من <https://www.python.org/downloads/windows/> وفعّل **Add python.exe to PATH** أثناء التثبيت |
| اتصال إنترنت | لتنزيل المكتبات مرة واحدة، ثم للاتصال بتيليجرام |
| API_ID و API_HASH | من <https://my.telegram.org> ← *API development tools* |

---

## 2) التشغيل السريع على Windows (الطريقة الأسهل)

1. افتح مجلد `tgmulti_panel`.
2. شغّل الملف **`start.bat`** بنقرة مزدوجة.
3. عند أول تشغيل سيقوم تلقائياً بـ:
   - إنشاء بيئة افتراضية `venv\`
   - تثبيت المتطلبات من `requirements.txt` (telethon، PyQt5 …)
   - إنشاء المجلدات `sessions\` و `logs\` و `data\`
   - فتح الواجهة
4. في المرات التالية يفتح الواجهة مباشرة (يعيد التثبيت فقط إذا تغيّر `requirements.txt`).

> إذا ظهرت نافذة سوداء وأُغلقت فوراً: افتح `cmd` داخل المجلد واكتب `start.bat` لترى رسالة الخطأ،
> أو راجع `logs\gui.log`.

---

## 3) التثبيت اليدوي (خطوة بخطوة)

افتح **موجه الأوامر (cmd)** أو **PowerShell** داخل مجلد `tgmulti_panel` ثم:

```bat
:: 1) إنشاء البيئة الافتراضية
py -3 -m venv venv

:: 2) تفعيلها
venv\Scripts\activate
::   (في PowerShell:  .\venv\Scripts\Activate.ps1 )
::   (في Linux/macOS: source venv/bin/activate )

:: 3) تثبيت المكتبات
python -m pip install --upgrade pip
pip install -r requirements.txt

:: 4) تشغيل الواجهة
python gui.py
```

في Linux تحتاج أيضاً مكتبات Qt النظامية (مثلاً على Debian/Ubuntu):
`sudo apt install libgl1 libxkbcommon-x11-0 libxcb-xinerama0`.

## 4) تنظيم مجلد الجلسات `sessions/`

الجلسات هي ملفات **Telethon `.session` القياسية (SQLite)** — لا حاجة لأي تحويل.
ضع كل مجموعة حسابات داخل **مجلد فرعي** باسم من اختيارك، والواجهة تعرض هذه المجلدات في قائمة منسدلة:

```
tgmulti_panel/
└── sessions/
    ├── سوريا_33_سبام/
    │   ├── +963900000001.session
    │   ├── +963900000001.json      ← اختياري (بيانات API خاصة بهذا الحساب)
    │   ├── +963900000002.session
    │   └── +963900000003.session
    ├── مصر_دفعة_1/
    │   ├── 201000000001.session
    │   └── 201000000002.session
    └── تجريبي/
        └── test.session
```

قواعد مهمة:

- اسم المجلد حرّ (عربي/إنجليزي/أرقام). اسم ملف الجلسة يُستخدم كاسم العرض (يُفضَّل رقم الهاتف).
- **لا تضع ملفات `.session` مباشرة داخل `sessions/`** — يجب أن تكون داخل مجلد فرعي.
- يمكنك اختيار أي مجلد آخر على القرص بزر **«📂 مجلد آخر…»**.
- الملف `*.json` المرافق اختياري. إن وُجد بجانب الجلسة وبنفس الاسم يُقرأ منه `app_id` / `app_hash`
  (وأيضاً `phone`, `first_name`, `username` للعرض). وإلا تُستخدم بيانات API المدخلة في الواجهة.
  مثال:
  ```json
  {"app_id": 1234567, "app_hash": "0123456789abcdef0123456789abcdef", "phone": "+963900000001", "first_name": "أحمد"}
  ```
- عند تحميل المجلد تفحص الواجهة كل ملف محلياً (بدون اتصال): وجود مفتاح تسجيل الدخول، رقم مركز البيانات (DC)،
  وسلامة ملف SQLite. الجلسات غير المسجَّلة دخول تظهر بعلامة ❌ ولا يمكن تحديدها.
- **لا تشغّل نفس ملف الجلسة من برنامجين في الوقت نفسه** (يسبب قفل قاعدة البيانات وأخطاء AuthKey).

## 5) استخدام الواجهة

1. **بيانات Telegram API**: أدخل `API_ID` و `API_HASH` (تُحفظ محلياً على هذا الجهاز فقط).
2. **الجلسات**: اختر المجلد من القائمة، ثم حدّد الحسابات المطلوبة بعلامات ✔ (أو «تحديد الكل» / «الصالحة فقط»).
3. **المهمة**: اكتب المهمة في المربع النصي — سطر أو عدة أسطر، مثل:
   ```
   https://t.me/SomeBot?start=123456
   ```
   ```
   /start
   subscribe @channel_name
   check
   ```
   ```
   https://t.me/some_channel/155
   تفاعل 🔥
   ```
   ```
   @my_channel      ← اشتراك في قناة فقط
   ```
4. **عدد الحسابات** و**السرعة** و**التأخير بين الحسابات** (بالثواني — نفس آلية المحرك الأصلي: قيمة عشوائية بين الحدّين).
5. اختر الوضع:
   - **🧠 تحليل بالذكاء الاصطناعي (موصى به)**: يحلل النص، يشرح خطواته بالعربية في السجل، ويسألك عبر نافذة عند وجود غموض
     (أكثر من بوت في النص، خطوات غير مفهومة، إلخ).
   - **⚡ تنفيذ مباشر**: يرسل المهمة للمحرك دون تحليل أو أسئلة. أول سطر هو الهدف، والأسطر التالية خطوات يدوية اختيارية
     (`start`, `subscribe`, `check`, `language`, `math`, `emoji`, `phone`, `visit`, `click: نص الزر`, `text: نص`,
     أو بالعربية `اضغط تحقق`, `ارسل مرحبا`).
6. **🙋 اسألني عند الحاجة أثناء التنفيذ**: عند تفعيله، إذا انخفضت ثقة الذكاء الاصطناعي أو تعثّر مع رسالة من البوت،
   تتوقف المهمة مؤقتاً وتظهر نافذة تعرض رسالة البوت وأزراره مرقّمة؛ اكتب رقم الزر أو نصاً ليُرسل للبوت ثم «إرسال».
   إن لم تُجب خلال **المهلة** المحددة يكمل الذكاء الاصطناعي تلقائياً بقراره الأصلي.
   كلمات خاصة داخل حقل الإجابة: `تم` = اعتبر المهمة مكتملة، `تخطي` = دع الذكاء الاصطناعي يقرر، `إيقاف` = أوقف هذه المهمة.
7. اضغط **▶ تشغيل**. تابع السجل الملوّن (✅ نجاح، ❌ خطأ، ⚠️ تحذير، 🧠 خطوات الذكاء الاصطناعي) وشريط الحالة.
8. **⏹ إيقاف** يوقف التنفيذ بأمان (يُغلق الاتصالات ثم يتوقف). **🧹 مسح السجل** ينظّف السجل، و«💾 حفظ السجل» يحفظه في `logs/`.
9. **🔍 تحليل فقط**: يعرض خطة الذكاء الاصطناعي دون تنفيذ (مفيد للتأكد من فهم المهمة).
10. **🌓 الوضع الداكن/الفاتح** من شريط الأدوات؛ الإعدادات (API، المجلد الأخير، المهمة الأخيرة، المظهر) تُحفظ تلقائياً.

## 6) أين تُحفظ البيانات؟

| المسار | المحتوى |
|---|---|
| `sessions/<مجلد>/` | ملفات الجلسات (لا يلمسها البرنامج إلا للقراءة/الاتصال) |
| `logs/worker.log` | سجل المحرك (بتدوير تلقائي 2MB × 3) |
| `logs/gui.log` | أخطاء الواجهة غير المتوقعة |
| `logs/gui_log_*.txt` | السجلات المحفوظة يدوياً من زر «حفظ السجل» |
| `data/bot_templates.json` | القوالب التي تعلّمها الذكاء الاصطناعي لكل بوت (تُعاد تلقائياً مع الحسابات التالية). يمكن مسحها من شريط الأدوات |
| إعدادات النظام (QSettings) | API_ID/API_HASH، المظهر، آخر مجلد ومهمة |

قائمة المهام (`tasks_queue`) وسجلات التنفيذ تُحفظ **في الذاكرة فقط** أثناء الجلسة وتُصفَّر مع كل ضغطة «تشغيل» — لا حاجة لأي قاعدة بيانات.

## 7) تشغيل المحرك من سطر الأوامر (بدون واجهة)

```bat
venv\Scripts\python worker.py --api-id 1234567 --api-hash 0123456789abcdef... ^
    --folder "سوريا_33_سبام" --task "https://t.me/SomeBot?start=123" --accounts 5 --speed medium
```

اكتب `python worker.py --help` لعرض كل الخيارات.

---

## 8) حل المشكلات الشائعة

| الرسالة / المشكلة | الحل |
|---|---|
| `لم يتم العثور على Python 3` | ثبّت Python وفعّل خيار PATH ثم أعد تشغيل `start.bat` |
| `ModuleNotFoundError: PyQt5` | شغّل من داخل venv: `venv\Scripts\python gui.py` أو احذف مجلد `venv` ليُعاد إنشاؤه |
| الجلسة تظهر ❌ غير مسجَّلة دخول | الملف لا يحتوي مفتاح تسجيل دخول؛ سجّل الدخول بها أولاً عبر Telethon |
| `database is locked` | نفس ملف الجلسة مفتوح في برنامج آخر — أغلقه ثم أعد المحاولة |
| `AuthKeyUnregistered` / `UserDeactivated` | الحساب محظور أو انتهت الجلسة — يُعطَّل تلقائياً ويُستبعد من الدفعة |
| `FloodWait` | تيليجرام يطلب الانتظار؛ المحرك ينتظر تلقائياً (زد التأخير بين الحسابات) |
| النافذة لا تظهر بشكل صحيح على Linux | ثبّت مكتبات Qt النظامية (انظر القسم 3) |

## 9) بنية المجلد

```
tgmulti_panel/
├── gui.py            ← الواجهة الرسومية (PyQt5)
├── worker.py         ← محرك التنفيذ (نفس المنطق الأصلي + مخزن محلي بدل Supabase)
├── ai_agent.py       ← محلل الرسائل ومحرك القرار (بدون أي تعديل)
├── task_planner.py   ← تحليل نص المهمة → خطة/أسئلة/خطوات (نفس قواعد main.py القديم)
├── local_store.py    ← مخزن محلي بواجهة مشابهة لـ Supabase (ذاكرة + data/)
├── requirements.txt
├── start.bat
├── sessions/         ← مجلدات الجلسات الفرعية
├── logs/             ← السجلات
└── data/             ← القوالب المتعلَّمة (يُنشأ تلقائياً)
```
